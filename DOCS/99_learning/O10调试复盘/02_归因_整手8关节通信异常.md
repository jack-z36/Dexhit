# 归因 ②：整只手 8 个关节都通信异常？

> **结论：❌ 被否定。** 批量读取接口有 bug，把 1 个关节的标记放大成了 8 个。是"工具读数骗人"，不是手坏了。

## 1. 观测（看到了什么）

- 用 SDK 的**批量接口** `get_all_error_reports()` 读错误报告，返回 **8 个关节全是 16**。
- 看起来像：整只手 8 个关节集体通信异常。

```
get_all_error_reports() 返回：
  关节1: 16    关节2: 16    ...    关节8: 16   ← 整手异常？
```

## 2. 推测（猜了什么 · 为什么这么猜）

**猜测：整只手的 8 个关节都通信异常。**

理由很直接：批量接口一次报 8 个，数据"看起来"很完整，谁都会信。

## 3. 验证（怎么证明这个猜测）

- 换**最小、最原始**的接口：单关节逐个读 `get_error_report(j)`（j=1..10）。
- 拿两种读法的结果**逐关节对比**。

## 4. 结果（验证怎么说）

- ❌ 单关节读：只有**零星几个关节**带标记，其余干干净净。
- ❌ 对比结论：**批量接口 `get_all_error_reports()` 本身有 bug**——它把 1 个关节的标记放大成了 8 个（读一个，报一片）。

```
单关节读（真相）：  关节3: 16   其余: 0
批量接口读（bug）： 关节1~8: 全是 16   ← 放大版
```

## 5. 结论与教训

**不是手坏了，是"温度计坏了"。** 批量接口这个"温度计"会把 1 度显示成 8 度。

> 教训②：**二次加工的数据会骗人**。看到异常先怀疑工具，回到源头用最小接口交叉验证。批量接口方便，但"方便"不等于"正确"。
