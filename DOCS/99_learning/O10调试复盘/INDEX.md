# O10 调试复盘 · 索引

> 面向人学习：一次真实硬件调试（Agilink OmniHand O10 左手 arm 失败）的完整归因过程。
> 记录时间：2025-08-18。本目录是 **99_learning 学习材料，非 Agent 默认上下文、非当前权威规则**。

## 背景一句话

左手 arm 失败、主控板"不应答"。逐层排查后真相是 **4 个问题叠加**：SDK 批量错误接口 bug、`commu_except` 历史标记被系统当致命故障锁存、provider 从不发布反馈、control 命令缺 `name`。全部修复后真机验证通过（arm 成功、手可运动）。

```
现象①：左手 arm 失败，返回 "fault is latched"
```

## 核心教训（六条）

1. **不要被"像故障的名字"吓住**——先验证链路是否真的断了（归因①）。
2. **二次加工的数据会骗人**——回到源头，用最小接口交叉验证（归因②）。
3. **字段语义以官方源码为准**，不按名字猜（归因③）。
4. **当所有外因都被否定，回到系统自身逻辑**找"加工错误"（归因④）。
5. **让日志说话**——provider 的拒收理由是最高效的定位线索；**先确认对方有没有能力**，再怀疑自己逻辑错（归因⑥⑦⑧）。
6. **多次采样区分"数据坏"还是"标准错"**——硬件的真实零位优先于配置里的理论限位（归因⑨⑩）。
