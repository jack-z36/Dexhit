# 模块边界与数据流

四个源码阶段对应四个稳定边界。阶段内部实现可以变化，但跨阶段只通过明确产物交接。

| 阶段 | 输入 | 主要职责 | 输出 |
| --- | --- | --- | --- |
| collection | 采集设备与场景动作 | 采集并记录原始观测、动作和必要元数据 | `raw MCAP` |
| processing | `raw MCAP` | 对时间、质量和字段进行处理，形成训练可用的数据集 | `LeRobotDataset v3` |
| training | `LeRobotDataset v3` | 训练、评估并打包策略模型 | `ACT bundle` |
| deployment | `ACT bundle` 与现场运行环境 | 加载策略、读取实时观测、输出执行命令并记录运行结果 | 现场执行与运行记录 |

## 边界原则

1. 上游阶段拥有其输出产物的生成责任，下游不得静默改写上游原始产物。
2. 每次跨阶段交付都应能指出输入、输出和验证结果；具体字段契约在阶段实现前不预设。
3. 处理和训练产生的缓存、日志、数据集和模型属于生成物，不应混入源码或文档。
4. deployment 依赖 training 的模型交付格式，但不把训练过程细节带入运行时接口。
