# O10 控制状态 ROS 接口契约

本文固定 Phase 1 O10 控制节点的逐侧可观测状态消息。状态用于操作者界面、诊断、MCAP 录制和验收，不作为控制输入；控制节点的安全判定不得依赖该状态 Topic，也不得依赖诊断用的 `RetargetingState`。

## 消息与 Topic

```text
rokoko_omnihand_msgs/msg/O10ControlState

/o10_control/left/state
/o10_control/right/state
```

消息字段固定为：

```ros
std_msgs/Header header

string side
uint8 event
uint8 phase

bool feedback_ready
bool error_monitor_ready
bool target_ready
bool target_fresh

bool fault_latched
bool motion_enabled

uint8 target_result
bool command_published
bool[10] slew_limited

uint32 fault_reason_mask
uint16[10] hardware_error_bits

bool target_time_available
builtin_interfaces/Time last_target_input_stamp
builtin_interfaces/Time last_target_received_stamp

bool command_time_available
builtin_interfaces/Time last_command_sent_stamp

bool feedback_time_available
builtin_interfaces/Time last_feedback_received_stamp

bool error_status_time_available
builtin_interfaces/Time last_error_status_received_stamp
```

`side` 只能是 `left` 或 `right`，且必须与 Topic 身份一致。10 维数组顺序与 O10 主动关节命令固定顺序相同：

```text
0 thumb_roll
1 thumb_abad
2 thumb_mcp
3 index_abad
4 index_pip
5 middle_pip
6 ring_abad
7 ring_pip
8 pinky_abad
9 pinky_pip
```

## 独立安全判据

控制节点不得通过订阅 `RetargetingState.ready` 或 `RetargetingState.stale` 决定是否向硬件发送命令。原因是该消息只用于诊断；消息丢失、延迟或状态节点异常不能改变安全状态机。

控制节点从自己的输入和本地状态独立派生：

- `feedback_ready`：已从硬件独立读取一帧新鲜、合法的真实 10 维主动关节状态，并据此初始化硬限速器；
- `error_monitor_ready`：已获得当前有效的 O10 错误状态，且错误轮询未超时；
- `target_ready`：本次控制进程中至少接收并验证过一条合法软目标；
- `target_fresh`：最近合法软目标的上游输入时间及本机接收时间均满足配置的新鲜度要求；
- `fault_latched`：该侧存在必须人工清除的锁存控制故障。

真正的运动许可严格定义为：

\[
\boxed{
\operatorname{motionEnabled}_s
\iff
\land \operatorname{feedbackReady}_s
\land \operatorname{errorMonitorReady}_s
\land \operatorname{targetReady}_s
\land \operatorname{targetFresh}_s
\land \neg\operatorname{faultLatched}_s
}
\]

`motion_enabled` 必须等于上式，不能作为可写开关。运动使能不再需要操作者 arm 授权：技术前置条件成立且目标新鲜即自动使能（与官方 SDK 行为一致）；每条新鲜合法软目标都事件驱动地产生一条硬件命令。

## 整体阶段

消息定义：

```ros
uint8 PHASE_INITIALIZING=0
uint8 PHASE_IDLE_NOT_READY=1
uint8 PHASE_IDLE_READY=2
uint8 PHASE_ACTIVE=3
uint8 PHASE_PAUSED_TARGET_STALE=4
uint8 PHASE_FAULT_LATCHED=5
```

| 阶段 | 含义 |
| --- | --- |
| `INITIALIZING` | 正在建立硬件连接、读取真实状态或建立错误监控 |
| `IDLE_NOT_READY` | 尚无新鲜目标，且至少一个技术前置条件尚不成立 |
| `IDLE_READY` | 技术前置条件成立，但尚无目标（等第一条目标即可运动） |
| `ACTIVE` | `motion_enabled=true`，可由新的合法目标触发发送 |
| `PAUSED_TARGET_STALE` | 曾有目标但已过期，停止发送；新目标到达即恢复 |
| `FAULT_LATCHED` | 锁存故障已置位，运动停止，必须人工清除 |

阶段是便于观察的状态汇总；当布尔字段与阶段发生冲突时，属于控制安全不变量失效，必须进入锁存故障，不能由消费者猜测哪个字段正确。

## 状态事件

状态采用事件驱动发布。`event` 至少定义：

```ros
uint8 EVENT_STARTUP=0
uint8 EVENT_TARGET_PROCESSED=1
uint8 EVENT_TARGET_TIMEOUT=2
uint8 EVENT_FEEDBACK_RECEIVED=3
uint8 EVENT_ERROR_STATUS_RECEIVED=4
uint8 EVENT_OPERATOR_REQUEST=5
uint8 EVENT_FAULT_CHANGED=6
uint8 EVENT_COMPONENT_STATE_CHANGED=7
```

- `STARTUP`：控制节点开始或单侧状态重新初始化；
- `TARGET_PROCESSED`：收到并完成一条软目标的验证与处理；
- `TARGET_TIMEOUT`：本地检查发现最近目标已不再新鲜；
- `FEEDBACK_RECEIVED`：收到并验证硬件主动关节反馈；
- `ERROR_STATUS_RECEIVED`：收到并处理一次主动查询的错误状态；
- `OPERATOR_REQUEST`：处理使能、解除使能或清除故障请求；
- `FAULT_CHANGED`：锁存故障或其原因集合发生变化；
- `COMPONENT_STATE_CHANGED`：Adapter、连接或设备状态发生变化。

不要求固定周期重复完全相同的快照；目标超时、反馈超时和错误监控超时仍必须由定时检查转换成对应事件。

## 软目标处理结果

`target_result` 表示最近一次 `TARGET_PROCESSED` 事件中的处理结果：

```ros
uint8 TARGET_NOT_EVALUATED=0
uint8 TARGET_SENT=1
uint8 TARGET_VALID_MOTION_DISABLED=2
uint8 TARGET_REJECTED_SCHEMA=3
uint8 TARGET_REJECTED_NAME_ORDER=4
uint8 TARGET_REJECTED_NONFINITE=5
uint8 TARGET_REJECTED_LIMIT=6
uint8 TARGET_REJECTED_AUX_FIELDS=7
uint8 TARGET_REJECTED_TIMESTAMP=8
uint8 TARGET_REJECTED_CONTROL_STATE=9
```

- `SENT`：目标合法、允许运动，并已生成且发布一条硬限速后的命令；
- `VALID_MOTION_DISABLED`：目标本身合法，但当前 `motion_enabled=false`，未向硬件发送；
- `REJECTED_*`：目标不满足对应契约或控制状态不允许处理。

非目标事件中 `target_result=TARGET_NOT_EVALUATED`。`command_published` 只表示本事件是否实际发布了硬件命令，不能由 `target_result` 之外的历史状态推断。

## 硬限速介入状态

`slew_limited[j]` 仅在 `command_published=true` 时有实际意义。若该事件中：

\[
\left|q^{\mathrm{send}}_{s,j}-q^{\mathrm{soft}}_{s,j}\right|>\varepsilon_{\mathrm{compare},j},
\]

则为 true；否则为 false。其中 \(\varepsilon_{\mathrm{compare},j}\ge 0\) 是只用于避免浮点比较误判的配置容差，不是新的运动阈值。没有发布命令时数组必须全为 false。

## 故障原因与硬件错误位

`fault_reason_mask` 是可组合位掩码：

```ros
uint32 FAULT_HARDWARE_ERROR=1
uint32 FAULT_COMMAND_READBACK_TIMEOUT=2
uint32 FAULT_INVALID_FEEDBACK=4
uint32 FAULT_SAFETY_INVARIANT=8
uint32 FAULT_COMPONENT_RESTART_OR_DISCONNECT=16
uint32 FAULT_ERROR_MONITOR_TIMEOUT=32
```

多个原因可同时置位。`fault_latched=true` 时掩码不得为 0；某个原始条件恢复后，可以更新原因观测，但不得自动清除锁存故障。

`hardware_error_bits[j]` 保存最近一次有效错误查询中第 \(j\) 个主动关节的厂商错误位原值，位语义由厂商接口定义。**任一关节的致命错误位**（bit0 `stalled`、bit1 `overheat`、bit2 `over_current`、bit3 `motor_except`）非零触发 `FAULT_HARDWARE_ERROR`；`commu_except`（bit4）是厂商定义的**历史通信异常标记**，官方 SDK 明确其不阻止厂商侧控制，故不触发故障锁存，但仍保留在 `hardware_error_bits` 原值中供诊断。在从未获得有效错误状态时，数组零值不代表硬件健康，此时由 `error_monitor_ready=false` 表达“未知”。

## 时间语义

`header.stamp` 是本条控制状态实际发布的 ROS 时间，`header.frame_id` 为空。

- `last_target_input_stamp`：最近一条合法软目标所携带的上游 `JointState.header.stamp`；
- `last_target_received_stamp`：控制节点收到该软目标的 ROS 时间；
- `last_command_sent_stamp`：最近实际发布硬件命令的 ROS 时间；
- `last_feedback_received_stamp`：最近有效硬件主动关节反馈的 ROS 接收时间；
- `last_error_status_received_stamp`：最近有效厂商错误状态的 ROS 接收时间。

每个时间都有独立 `*_time_available`。可用位为 false 时，消费者不得解释对应零时间；不能用零值本身区分“尚未发生”和真实时间。硬限速的 \(\delta t\) 仍使用控制节点本机单调时钟，不使用这些 ROS 时间字段。

## 发布与录制规则

两侧状态独立发布，一侧故障不阻断另一侧。状态 Topic 必须可由外部 rosbag2/MCAP 录制，控制节点不直接写 MCAP。该消息是可观测结果，不得反向驱动故障清除、目标验证或命令发送。
