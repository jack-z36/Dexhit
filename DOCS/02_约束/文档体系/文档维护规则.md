# 文档维护规则

本文件合并旧约束中的文档分类、上下文路由、AGENTS 纯度、语义迁移、归档和学习资料隔离规则，是 Dexhit 文档体系的唯一维护规则。

## 1. DOCS 固定分类

```text
DOCS/
├── 01_知识/
├── 02_约束/
├── 03_工程/
├── 98_archive/
└── 99_learning/
```

| 分类 | 回答的问题 | 可以放 | 不可以放 |
| --- | --- | --- | --- |
| `01_知识` | 项目是什么、数据如何流动、为什么这样设计 | 稳定事实、概念、模块边界、数据流 | 当前进度、执行日志、强制规则 |
| `02_约束` | 做事时必须遵守什么 | 术语口径、编程执行、文档治理 | 项目百科、当前状态、历史执行过程 |
| `03_工程` | 当前具体推进到哪里 | 状态、任务资产、验收、debug、运行手册 | 稳定规则的重复副本 |
| `98_archive` | 历史上发生过什么 | 旧快照、迁移审计、已失效材料 | 当前权威入口、持续维护的进度 |
| `99_learning` | 人需要学习什么 | 外部资料、教程、长篇解释 | Agent 默认上下文、当前权威规则 |

`DOCS/` 根目录不新增散落阶段目录或零散规则文件。内容同时包含多种语义时按语义拆分，不按旧文件名整体搬运。

## 2. 三类约束固定边界

`DOCS/02_约束/` 除 `INDEX.md` 外只保留：

- `用户概念体系/`：用户定义的术语、阶段名称、模块口径和表达偏好。
- `编程执行/`：上下文加载、需求澄清、代码修改、测试、Debug、Git、文件落点和 Skill。
- `文档体系/`：分类、索引、路由、迁移、archive 和 learning 隔离。

不再创建 Git 协作、上下文加载、文件存放、工作流、任务体系或技能体系等平级目录；仍有效的规则归入上述三个入口。

## 3. INDEX 规则

每个受管理的 `DOCS/` 目录必须有 `INDEX.md`。INDEX 只包含：

- 本目录职责与不负责内容。
- 本目录的当前权威文件。
- 直属子目录入口。

INDEX 不复制规则正文、知识正文、项目主链、当前进度或历史解释。新增、移动、重命名或删除文档时，必须同步检查：

1. 目标目录 INDEX。
2. 来源目录 INDEX。
3. 两者的父级 INDEX。
4. 其他直接引用该路径的 Markdown 链接。

空目录仍属于受管理目录时也必须有 INDEX；不再承担职责的空目录应删除。

## 4. 根 AGENTS 路由纯度

仓库只保留一个全局 `AGENTS.md`，位置在根目录。它只回答“这类任务开始前读取哪个权威入口”，允许包含任务名称、触发说明、入口路径和默认禁止读取区。

根 `AGENTS.md` 不得包含：

- 项目主链、业务背景或当前能力说明。
- 模块实现、运行命令、测试命令或 Git 工作流正文。
- 规则全文、状态、执行记录、debug 结论或历史方案。

不得在 `DOCS/` 子目录新增局部 `AGENTS.md`。修改路由前先确认目标规则文件存在、链接有效且职责单一。

## 5. 按任务类型加载上下文

根路由指向权威入口后，按任务最小化加载：

### 知识查询或原理解释

先定位主题并读取相关 `01_知识` 页面。只有问题涉及当前推进证据时读取对应 `03_工程`；涉及规则边界时才读取 `02_约束`。回答必须区分当前权威、历史参考和推断。

### 理解、规划或新功能蓝图

先读取用户概念体系和相关知识，再读取编程执行约束与当前工程状态。只有准备正式创建文档时才读取具体模板；产出前说明文档类型、目标路径、适用范围和未知问题。

### 编码、测试、Debug、Git 或 Skill

读取编程执行入口，再按直接依赖定点加载相关知识、代码、测试和工程状态。详细执行规则不拆成新的上下文加载文件。

### 文档体系维护

先读取本文件和相关 INDEX，再建立或更新语义迁移审计，最后定点读取来源和目标文档。输出说明新增、拆分、合并、归档、废弃的语义及仍未处理的来源。

## 6. 默认禁止读取区

默认不扫读：

- `DOCS/98_archive/`
- `DOCS/99_learning/`
- 大型外部资料
- 历史执行日志全文
- 与当前问题无关的阶段工程目录和模板目录

用户明确要求历史复盘、迁移复核或学习资料时，只读取直接相关文件。不能用归档规则覆盖当前权威，也不能从历史状态推断当前状态。

## 7. 语义迁移流程

迁移单位是可独立判断的语义，不是文件。一个旧文件可以拆到多个目标，多个旧文件的重复语义应合并到一个权威入口。

固定流程：

1. 清点全部来源文件，标记重复文件和模板。
2. 按标题或规则单元拆出语义，判断是知识、约束、工程、learning 还是 archive。
3. 判断语义是继续有效、需要改写、仅历史有效还是废弃。
4. 将有效语义写入唯一目标；不保留无人维护的并列权威副本。
5. 更新目标和父级 INDEX、根路由及所有相对链接。
6. 在审计表中登记每个来源或明确的来源组及处理动作。
7. 验证目录形状、INDEX 覆盖和相对链接后，将审计表归档。

迁移审计字段固定为：

```text
source_path | source_heading | 语义摘要 | 语义类型 | 目标路径 | 处理动作 | 是否权威 | 备注
```

`语义类型` 只能是 `知识`、`约束`、`工程`、`learning`、`archive`。

`处理动作` 只能是 `抽取新建`、`合并去重`、`原样迁移`、`标记历史`、`移入learning`、`废弃但归档保留`。

禁止根据 `背景信息.md`、`执行约束.md` 等旧文件名直接决定分类；禁止把含有历史规则的执行日志作为当前规则；禁止迁移后留下多个声称权威的入口。

## 8. 本次 ROS 约束迁移边界

迁移到当前权威入口的通用语义包括：

- 阶段与产物的统一称谓、概念定义完整性和事实状态表达。
- 任务类型识别、上下文最小加载、需求澄清、现有实现盘点、契约差异、接口对齐、TDD、Debug、验证证据、回滚和高风险执行。
- 文件和生成物隔离、Git 安全、Skill 单一权威。
- 文档分类、INDEX、根路由、语义迁移和 archive/learning 隔离。

不迁移为当前规则的旧项目专属语义包括：

- L1/L2/L3 文件体系、dispatch、任务池、循环状态机和 Gate 调度角色。
- 旧阶段长期分支、功能分支接力、固定机器分工和自动提交策略。
- 旧 ROS 包、硬件包、脚本、绝对路径、运行入口和具体消息 schema。
- 旧阶段工程目录、模板和验收卡片路径。

其中具有普适价值的原则可以改写后抽取，但不得保留旧名、旧层级或旧路径依赖。

## 9. archive 与 learning 隔离

`98_archive` 中的文件保留当时语境，不继续维护为当前规则。`99_learning` 只面向人的学习；两者 INDEX 都必须明确“非默认上下文”。

从 archive 或 learning 发现仍有效语义时，将它抽取到 `01_知识`、`02_约束` 或 `03_工程`，更新审计和索引；不要直接修改历史文件使其重新成为权威。

## 10. 路径、链接与完成检查

- 仓库内路径使用相对仓库根目录的写法，不写开发者机器绝对路径。
- Markdown 链接使用相对目标文件路径，并在移动后验证可解析。
- 当前文件不得依赖已删除目录；历史来源只登记在 archive 审计表。
- 文档任务完成前检查所有 `DOCS` 目录拥有 INDEX，`02_约束` 仍只有三类，根路由链接有效，archive/learning 未进入默认路由。
