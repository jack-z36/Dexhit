# Agent 三层记忆与上下文检索规则

## 目的

本规则定义 Dexhit 工作区中 Agent 可使用的三层长期记忆、各层权威来源，以及按任务加载上下文的顺序。目标是让 Agent 读取最少但足够的上下文，并避免规则、项目语义和当前代码事实互相复制或覆盖。

```text
                 AI Workspace Memory
                         │
        ┌────────────────┼────────────────┐
        ▼                ▼                ▼
  ① 行为记忆         ② 项目记忆         ③ 代码记忆
  How to work        What / Why         What exists
```

| 层级 | 核心问题 | 本质 | 当前权威入口 |
| --- | --- | --- | --- |
| ① 行为记忆 | Agent 应该怎么做？ | Procedure / Rules | 根 [`AGENTS.md`](../../../AGENTS.md)、[`02_约束/`](../INDEX.md)、[`skills/`](../../../skills/INDEX.md) |
| ② 项目记忆 | 项目是什么？为什么这样设计？ | Semantic Knowledge | [`01_知识/`](../../01_知识/INDEX.md) |
| ③ 代码记忆 | 当前代码实际上是什么？ | Code Ground Truth Index | 当前 worktree 的 [`src/`](../../../src/) 及与之对应的 Code Graph、AST、LSP 等派生索引 |

最简定义：

```text
第一层：How
        Agent 怎么干活

第二层：What + Why
        项目是什么，为什么这么设计

第三层：Is
        代码现在实际上是什么
```

最高原则：

> 第一层约束 Agent，第二层解释项目，第三层描述现实。三层互不复制。

## ① 行为记忆：规定 Agent 怎么工作

行为记忆保存执行任务时必须遵守的方法、规则、流程和约束，包括：

- 任务开始时读取什么、按什么顺序读取；
- 代码修改、测试、Debug、Git 和文档维护规则；
- 特定任务何时触发以及如何执行 Skill；
- 哪些目录、数据和操作具有安全边界。

行为记忆不解释项目目标、设计理由、当前实现关系或当前工程进度。若一条信息回答“Agent 下一步应该怎么行动？”，它属于行为记忆。

行为记忆的职责分工：

- 根 `AGENTS.md` 只负责按任务类型路由到权威入口；
- `02_约束/` 保存长期、普遍适用的执行规则；
- `skills/` 保存命中特定触发条件后才加载的专项流程，不得默认全量读取。

## ② 项目记忆：保存项目世界模型

项目记忆保存无法仅靠当前代码完整推导、且对长期理解或重建项目仍有价值的稳定语义，包括：

- 项目目标、范围和系统边界；
- 宏观架构、数据流和模块职责；
- 硬件、运行环境、坐标系与数据契约；
- 接口语义、安全边界和系统级约束；
- 关键设计选择及其理由。

项目记忆不记录函数行号、调用者数量、当前文件树、一次性 Bug 修复或当前开发进度。若代码全部删除后，一条信息仍对重建项目有价值，它大概率属于项目记忆。

项目记忆从 [`01_知识/INDEX.md`](../../01_知识/INDEX.md) 开始按需读取。先读索引和与任务直接相关的知识页，不默认展开整个目录。

## ③ 代码记忆：保存当前代码事实

代码记忆描述当前源码中可自动提取和查询的结构与关系，包括：

- 文件、类、函数、变量和其他符号；
- 定义、引用、调用与被调用关系；
- 导入、包含、继承、实现、类型使用和依赖；
- 当前模块连接、调用路径和修改影响范围。

这些事实不得由人工维护的 Markdown 充当权威副本。Code Graph、AST、LSP 或 MCP 只用于索引和检索，第三层的最终 Source of Truth 永远是当前 worktree 的源码。

代码检索必须遵守：

1. 查询定义、引用、调用路径、依赖或影响范围时，优先使用可用的结构化代码索引定位目标。
2. 作出修改或结论前，回到当前 worktree 的相关源码和测试确认关键事实。
3. 仅使用与当前仓库、分支、worktree 和版本对应的索引；无法确认对应关系时，把索引视为线索而非证据。
4. 不同 worktree 的代码事实相互独立，不得让另一个 worktree 或旧版本的图谱覆盖当前源码。
5. 没有结构化索引时，直接通过源码搜索、语言工具和测试建立所需事实，不为此手工编写代码结构文档。

## 三层之外：工程状态是短期工作上下文

[`03_工程/`](../../03_工程/INDEX.md) 记录当前进度、待办、阻断和推进资产。它是任务协作用的短期工作上下文，不是第四层长期记忆，也不得混入稳定项目知识。

只有任务涉及当前进度、后续工作、正在实施的方案，或编码规则明确要求时，才读取 [`03_工程/00_当前状态.md`](../../03_工程/00_当前状态.md)。代码是否已经存在仍由当前 worktree 验证，不能只依据状态文档判断。

`98_archive/` 和 `99_learning/` 同样不属于三层当前权威记忆。除非任务明确要求历史追溯、迁移复核或学习资料，否则不得加载。

## 按任务检索上下文

每个任务都按以下顺序建立上下文；“按需”表示只有该层能回答任务中的具体问题时才继续读取：

1. **识别任务类型**：读取根 `AGENTS.md`，一个任务可同时命中多个类型。
2. **加载行为记忆**：读取表中命中的约束入口；只有符合触发条件时才读取具体 Skill。
3. **加载项目记忆**：从 `01_知识/INDEX.md` 选择与任务对象直接相关的页面。
4. **加载工程状态**：任务涉及进度、计划、阻断或正在实施的工作时读取 `03_工程/`。
5. **查询代码记忆**：任务涉及当前实现、符号关系、影响范围或代码修改时，查询当前 worktree 及其派生索引。
6. **核对边界与冲突**：确认每个结论来自能够回答该问题的权威层；发现层间不一致时显式报告，不静默合并。

| 任务类型 | 必读行为入口 | 按需项目记忆 | 工程状态 | 代码记忆 |
| --- | --- | --- | --- | --- |
| 理解项目、规划、讨论术语 | 用户概念与术语规则 | 相关知识页 | 涉及当前推进时读取 | 涉及当前实现时查询 |
| 编码、测试、Debug | 编程执行规则、命中的 Skill；涉及术语或文档时追加对应规则 | 相关架构、数据流、契约与设计理由 | 读取当前相关状态 | 必须查询并以当前源码确认 |
| Git 或代码影响分析 | 编程执行规则、命中的 Skill | 只读取与变更语义相关的知识 | 涉及在途工作时读取 | 查询 diff、定义、引用、调用和测试 |
| 创建、迁移或维护文档 | 文档维护规则；涉及术语时追加用户概念规则 | 读取被记录主题的权威知识 | 只在文档记录工程进度时读取 | 仅在文档结论涉及当前代码事实时查询 |
| 查询具体任务进度 | 根路由和相关执行规则 | 仅为解释任务语义时读取 | 必须读取 | 需要确认“是否已实现”时查询 |
| 历史追溯或学习资料 | 文档维护规则 | 当前知识只用于对照 | 按问题读取 | 涉及历史代码时必须明确版本，不能冒充当前事实 |

## 冲突与时效性处理

三层回答不同问题，因此不能用某一层覆盖另一层：

- **行为冲突**：以根路由指向的当前约束和命中任务的专项 Skill 为执行依据；发现规则互相冲突时停止扩展操作并指出冲突。
- **项目语义与代码不一致**：项目记忆说明目标、边界或设计意图，当前源码说明实际实现。分别陈述“预期”和“现状”，不能擅自把任一方改写为另一方。
- **代码索引与源码不一致**：以当前 worktree 源码为准，并把图谱或索引标记为过期或不匹配。
- **工程状态与现场证据不一致**：以当前文件、测试和 Git 状态判断实际进展，并在任务授权范围内修正状态文档。
- **历史资料与当前资料不一致**：历史资料只用于说明演变，不得作为当前规则、项目事实或代码事实。

## 信息落点判定

新增或更新信息时按顺序判断：

1. 它是否规定 Agent 下一步应该怎么行动？是则进入行为记忆。
2. 它是否描述长期稳定的项目含义、边界或设计理由？是则进入项目记忆。
3. 它是否可从当前源码自动得到，且会随实现变化？是则保留在源码和自动派生的代码索引中，不手工复制到知识文档。
4. 它是否描述当前进度、待办、阻断或仍影响推进的阶段性验证结论？是则进入 `03_工程/`，不进入三层长期记忆。
5. 它是否只是运行日志或无需继续追踪的一次执行结果？是则不进入权威文档；仅有历史或教学价值时，分别进入 `98_archive/` 或 `99_learning/` 并保持默认隔离。

| 当前开发任务、待办和阻断 |  |  |  | ✅ |

## 维护要求

- 三层之间只建立链接，不复制正文；同一语义只保留一个当前权威入口。
- 新增、移动或删除文档时，按[文档维护规则](文档维护规则.md)同步更新本级和父级 `INDEX.md`。
- 稳定项目语义发生变化时更新 `01_知识/`；执行方式发生变化时更新 `02_约束/`；实现变化通过源码和派生索引反映。
- 自动代码索引应可识别其仓库、worktree 和源码版本；无法证明新鲜度时不得作为唯一依据。
- 完成导致进度或阻断发生变化的任务后，应同步维护相关工程状态，但不得把执行日志搬入知识或约束。
