# Rokoko 到 OmniHand O10 实时遥操作系统 Spec

状态：ready-for-agent

## Problem Statement

操作者希望佩戴 Rokoko Smartgloves 后，用左右手的实时手指动作控制对应的 OmniHand O10 灵巧手。系统需要覆盖张合、单指屈伸、拇指外展与对掌、捏合、双手不同步动作等常用手势，同时不能把人体手型差异、Rokoko 异常帧、IK 失败、消息积压或硬件故障直接转化为危险的关节跳变。

当前仓库只有一个 O10 双侧控制入口：它对 10 维位置做有限值和左右手限位校验后直接转发。仓库尚没有 Rokoko JSON v3 接收节点、人体到 O10 的重定向节点、版本锁定的 O10 在线运动学资产、自定义 ROS 消息、软平滑、反馈初始化硬限速、使能与错误监控和完整的无真机端到端测试链。因此，当前实现不能完成“戴上手套即可安全控制 O10”的目标，也不能证明异常时左右手隔离、数据不积压、故障不自动恢复等安全行为。

Phase 1 需要建立一条可运行、可观察、可录制、可在无真实硬件环境中自动验收的实时遥操作链。具体数值参数允许先保持可配置并通过官方样例、离线模型实验和未来真机试验标定，但接口、数学语义、状态机、失败行为和测试边界不得由实现者自行猜测。

## Solution

建立三个稳定功能模块组成的双手实时控制链：Rokoko 接收节点从 UDP 接收 JSON v3 场景数据并发布左右独立的原始手部帧；手部重定向节点从每侧 21 节点构造人体解剖学手掌坐标系、估计并冻结操作者五指长度、生成尺度归一化的 O10 指尖目标、通过带主动—被动耦合的单指 IK 求解 10 个主动关节并进行软平滑；O10 控制节点独立验证软目标、管理运动使能与锁存故障，并基于新鲜真实反馈施加最终关节变化率硬限制后交给硬件 Adapter。

左右手在接收、重定向、控制、状态和故障上彼此独立。诊断状态用于观察和 MCAP 录制，不反向参与控制安全判定。系统启动、重新连接或故障清除都不能凭零位、范围中点、上游首目标或旧缓存猜测实体手位置；必须通过 Adapter 独立读取一帧可信的 10 维主动关节反馈，才能初始化最终硬限速器。

自动化验收不连接真实 O10。测试以完整 ROS 图为主接缝，从 Rokoko JSON v3 UDP 测试源进入真实接收、重定向和控制节点，在末端使用纯软件硬件 Adapter 模拟真实关节反馈、错误位、查询超时、回读超时、重启和断连。测试通过公开 Topic 与 Service 观察 RawHandFrame、软目标、最终命令、反馈和状态，不调用节点私有算法。解析梯度、机械耦合、模型结构和资产完整性另以离线契约检查验证。

## User Stories

1. As an 操作者, I want 戴上 Rokoko Smartgloves 后用自己的左手控制 O10 左手, so that 机器人动作与我的逻辑手侧一致。
2. As an 操作者, I want 用自己的右手独立控制 O10 右手, so that 单手场景不要求另一只手存在。
3. As an 操作者, I want 同时控制左右 O10 且两侧可以做不同动作, so that 我能完成双手协同示范。
4. As an 操作者, I want 张开和闭合五指能够被重定向, so that 基础抓取手势可直接表达。
5. As an 操作者, I want 单独屈伸任一手指, so that 精细手势不会被强制变成整手联动。
6. As an 操作者, I want 拇指滚转、外展和屈伸得到表达, so that 对掌和捏合动作可实现。
7. As an 操作者, I want 拇指与各手指形成捏合目标, so that 常用精细操作能映射到 O10。
8. As an 操作者, I want 系统自动适应本次运行中我的手指长度, so that 不同操作者的绝对手型不会直接扭曲 O10 目标尺度。
9. As an 操作者, I want 每次程序启动自动重新估计并冻结我的五指长度, so that 不需要维护个人手型档案。
10. As an 操作者, I want 长度冻结后本次运行不再静默改变, so that 同一动作的尺度映射保持稳定。
11. As an 操作者, I want 五指长度全部稳定且五指都有首次有效 IK 后才产生控制目标, so that 系统不会用默认姿态填补未知手指。
12. As an 操作者, I want 偶发单指输入或 IK 失败时只保持该指上一有效目标, so that 其他合法手指仍能继续响应。
13. As an 操作者, I want 掌坐标系退化或整侧输入非法时该侧暂停输出, so that 无法解释的几何不会驱动整只手。
14. As an 操作者, I want 一侧坏包、IK 失败或故障不阻断另一侧, so that 双手链路具有故障隔离。
15. As an 操作者, I want Rokoko 断流或数据过期时停止产生新目标, so that O10 不会继续追赶过期的人体动作。
16. As an 操作者, I want 输入恢复经过连续完整有效帧和最短观察时间确认, so that 单个偶然好帧不会立即恢复运动。
17. As an 操作者, I want stale 恢复先保持旧软目标再有界追赶当前动作, so that 恢复首帧不会产生大跳变。
18. As an 操作者, I want 节点启动或上游数据刚出现时不会自动移动机械手, so that 只有反馈、错误监控、目标全部就绪且目标新鲜后才会运动。
19. As an 操作者, I want 每一侧只要反馈就绪、错误监控就绪且目标新鲜就自动运动（对齐官方 SDK 直控）, so that 我不需要再逐个手侧执行 arm。
20. As an 操作者, I want 技术前置条件尚不成立或目标过期时该侧不产生硬件命令, so that 未就绪或数据陈旧时系统不会擅自驱动实体手。
21. As an 操作者, I want 只要停止发布新目标（目标过期自动暂停）即停止运动, so that 停止控制无需任何额外调用。
22. As an 操作者, I want 运动暂停时手部保持在最后目标而不自动张手、回零或断开驱动, so that 暂停不会引入另一种意外运动。
23. As an 操作者, I want 硬件错误触发锁存故障并停止运动, so that 错误消失后系统也不会自动恢复运动。
24. As an 操作者, I want clear_fault 先确认错误位清零、通信健康并重新读取真实位置, so that 只有恢复可信硬件基准后才清除锁存。
25. As an 操作者, I want clear_fault 成功后不立即运动, so that 清故障不会直接启动机械手，而是等下一条新鲜目标。
26. As an 操作者, I want 控制操作返回机器可读结果码和可读说明, so that UI 和人工排查都能理解结果。
27. As an 操作者, I want 每个操作返回操作后的同侧控制状态, so that 不必等待另一个状态消息猜测执行结果。
28. As an 操作者, I want 单指 IK 残差按 O10 指链长度归一化, so that 长短不同的手指使用公平的求解质量标准。
29. As an 算法开发者, I want 优化器停止原因与候选解有效性分开, so that 达到时间上限但质量合格的解可接受，正常收敛但残差超标的解会被拒绝。
30. As an 算法开发者, I want 首次 IK 从关节范围中点开始且后续使用上一有效解 warm start, so that 搜索具备确定性和时间连续性。
31. As an 算法开发者, I want 只优化 O10 主动关节并解析派生被动关节, so that 求解空间与实际可命令自由度一致。
32. As an 算法开发者, I want 使用 O10 MJCF 的非线性耦合多项式, so that FK 不依赖 URDF 线性 mimic 近似。
33. As an 算法开发者, I want 使用 Pinocchio 完整指链平移雅可比和耦合雅可比组成解析梯度, so that SLSQP 获得正确的主动关节优化方向。
34. As an 算法开发者, I want 用中心差分离线验证解析梯度, so that 左右手、五指和拇指耦合差异都能被回归测试捕获。
35. As an 算法开发者, I want IK 后再对 10 维主动关节目标做按时间间隔更新的一阶低通, so that 抖动降低而 IK 损失本身保持清晰。
36. As an 安全开发者, I want 最终硬限制以上一条实际发送命令为位置基准, so that 上游不能绕过每关节变化率限制。
37. As an 安全开发者, I want 硬限制使用本机单调时钟并封顶单次时间额度, so that ROS 时间调整或长时间停顿不会放大允许跳变。
38. As an 安全开发者, I want 控制节点只在收到新目标时事件驱动地发送一条命令, so that 上游停止后不会有内部定时器继续追赶旧目标。
39. As an 安全开发者, I want 每次目标处理失败都不推进位置和时间基准, so that 无效帧不会消耗或制造下一次运动额度。
40. As an 安全开发者, I want 控制安全门只依据控制节点自己验证的目标、反馈、错误监控和故障状态, so that 诊断 Topic 丢失或延迟不会改变运动许可。
41. As an 系统集成者, I want 逻辑手侧与 CAN 通道、USB 路径和设备 ID 解耦, so that 更换通信配置不改变上游重定向接口。
42. As an 系统集成者, I want O10 几何与耦合资产来自同一锁定版本, so that URDF 和 MJCF 不会静默错配。
43. As an 系统集成者, I want 在线模型通过 ROS 安装空间查找, so that 正式运行不依赖开发者机器的绝对路径。
44. As an 系统集成者, I want 启动时校验资产哈希、关节、frame、限位和六条耦合, so that 模型错误在发送目标前被发现。
45. As an 系统集成者, I want 模型许可未确认时不把上游资产正式复制进项目, so that 技术开发不造成未经确认的再分发。
46. As an 数据工程师, I want Raw、软目标、最终命令、反馈和状态都可由外部 rosbag2/MCAP 录制, so that 离线分析能追踪每级转换和安全介入。
47. As an 数据工程师, I want RawHandFrame 保留 Rokoko 世界坐标和源四元数, so that 原始信息不会被重定向算法覆盖。
48. As an 数据工程师, I want RawHandFrame 记录本机 UDP 接收时间和原始 source_timestamp, so that 本机延迟分析与未知源时基保持区分。
49. As an 数据工程师, I want 同一 JSON 场景中的双手共享接收时间, so that 双手录制能够对齐。
50. As an 数据工程师, I want 软目标继承触发它的 Raw 接收时间, so that 控制节点能独立判断端到端目标年龄。
51. As an 维护者, I want 接收节点按名称重排 21 节点而不是相信源数组顺序, so that Rokoko 字段顺序变化不会静默串指。
52. As an 维护者, I want 非法 JSON、缺失 Actor 和非法手侧具有明确丢弃语义, so that 坏包不会终止接收进程或污染另一侧。
53. As an 维护者, I want RetargetingState 逐指报告长度、IK、残差、求解器和历史保持状态, so that 无真机环境也能定位重定向失败原因。
54. As an 维护者, I want O10ControlState 报告目标处理、限速介入、错误位、故障和关键时间, so that 控制安全状态可以通过公开接口验收。
55. As an 测试开发者, I want 从 JSON/UDP 到软件 Adapter 运行真实 ROS 节点, so that 自动测试覆盖跨节点契约而不依赖真实硬件。
56. As an 测试开发者, I want 软件 Adapter 可模拟反馈、错误、超时、重启和断连, so that 锁存故障与恢复流程可以确定性复现。

58. As an 测试开发者, I want 测试运行绝不访问真实硬件通信入口, so that CI 和开发机不会意外驱动 O10。

61. As an 操作者, I want 发布频率可人为设置为低于 IK 可持续吞吐, so that Phase 1 在未实现过载调度前仍能稳定运行。

## Implementation Decisions

1. Phase 1 固定为三个功能模块：Rokoko 接收节点、手部重定向节点和 O10 控制节点。外部硬件 Adapter 是厂商/设备隔离层，不计为第四个业务功能模块；无真机测试使用与其接口相同的纯软件 Adapter。
2. 系统只控制左右 O10 的 10 个主动手指关节，不控制腕部、机械臂、触觉、力矩或 6 个被动关节。左右逻辑侧可独立存在、独立失败，运动由各自侧别的新鲜目标驱动。
3. Rokoko 接收节点只接受 JSON v3。Actor 数组索引可配置，默认 0；一次运行只选择一个 Actor。官方 JSON v3 样例必须成为版本化 fixture，真实字段和 21 个节点原始拼写由 fixture 固定，不能由实现者猜测。
4. 接收节点在 UDP 数据包进入时立即取得 ROS 接收时间。合法双手来自同一场景包时共享该时间。场景级 `source_timestamp` 原样记录，在单位和 epoch 未由真实样例确认前不得参与控制计时或与 ROS 时间相减。
5. 接收节点向 `/rokoko/left/raw_hand` 和 `/rokoko/right/raw_hand` 发布 `RawHandFrame`。消息包含 header、Actor 索引和名称、原始 source timestamp、规范顺序的 21 个名称、位置和四元数；手侧由 Topic 表达。
6. 21 节点语义顺序固定为 Hand，随后按 Thumb、Index、Middle、Ring、Little，每指 Proximal、Medial、Distal、Tip。实现按真实节点名唯一匹配和重排，不信任 JSON 原数组顺序。
7. Raw 位置保留 Rokoko 世界坐标，不做换算、相对化、镜像、滤波或归一化。四元数保留为 x、y、z、w，要求有限且范数不接近零，不自动修正非单位值。
8. 场景级 JSON 失败或 Actor 不存在时双侧均不发布。一侧缺失或非法时只丢该侧，合法另一侧继续发布。坏包不终止进程，不补零、不复制另一侧、不复用历史帧。
9. Raw 发布 QoS 为 Reliable、Volatile、KeepLast(10)，深度 10 是可配置默认值。重定向订阅 QoS 为 BestEffort、Volatile、KeepLast(1)。外部 MCAP 录制器对 Raw 请求 Reliable、Volatile。Deadline 和 Lifespan 保持默认且不参与安全判定。
10. Phase 1 正常运行前提是 Rokoko 发布频率低于 IK 可持续吞吐。KeepLast(1) 只限制违反该前提时的旧帧积压；不新增 latest-only 调度线程或过载状态机。
11. 重定向节点按左右侧分别维护所有人体长度、IK、滤波、stale 和恢复状态；不得共享单例历史。
12. 人体解剖学手掌坐标系逐帧由 Hand 位置和四指 Proximal 几何构造。Hand.rotation 只保留在 Raw 数据中用于记录和诊断，不参与人体归一化/掌坐标算法。
13. 人体掌坐标使用掌根到四指根部中心定义纵向轴，以左右手约定的掌宽方向经正交化定义横向轴，并以叉乘定义第三轴。任一轴低于有效范数阈值时整侧当前帧无效，不执行除法归一化或 IK。
14. 每侧使用一个固定正交方向映射矩阵，把人体解剖学掌坐标向量映射到规范 O10 掌坐标。该矩阵只依赖逻辑侧和锁定模型，一侧五指共享，与操作者、当前帧和 FK 后端无关。
15. 每根人体手指长度按相邻节点线段之和计算。每次进程启动重新收集合法样本，用滑动窗口中位数和归一化中位绝对偏差判断稳定；连续 K 个完整稳定窗口后冻结该指估计。五指全部冻结前该侧不输出软目标。
16. 一次运行假设同一操作者和同一 Rokoko Actor Profile。冻结长度不在运行中静默更新。冻结后某指当前长度相对偏差超限时只使该指输入无效；若异常影响掌坐标所需节点，则整侧当前帧无效。
17. O10 指尖目标以对应 O10 指根为起点，把人体掌坐标中的根到指尖方向除以冻结人体完整指链长度，再乘 O10 完整指链长度，并应用固定方向映射。O10 指根和指链长度从锁定模型计算，不维护手写几何常量表。
18. 规范 O10 掌坐标固定为右侧 R_palm 和左侧 L_palm；掌根参考点就是该 frame 原点。FK 后端必须把所有结果适配到该规范坐标后再参与损失。
19. 在线模型使用专用无节点 ROS 资产包，通过 ROS 包索引从安装空间加载。核心资产仅包含左右生成态 URDF、左右 MJCF 和 provenance 清单；Xacro、碰撞模型、MuJoCo 场景、网格和 RViz 配置不是在线依赖。
20. URDF 是几何、关节、限位、指根和 tip frame 来源。Pinocchio 加载时显式关闭 mimic 并断言 nq=nv=16。不得依赖 PyBullet 或 Pinocchio 自动执行 URDF mimic。
21. MJCF 只作为六条主动—被动 `equality/joint` 多项式的数据源。严格加载器校验预期名称、唯一性、五个有限系数、左右差异和派生输出范围。运行时从主动变量显式计算被动关节，不假定普通 FK 或 MuJoCo 自动消元。
22. 模型 provenance 固定上游仓库 commit 和每个核心文件 SHA-256。CI 与启动都验证哈希和模型结构。上游许可正文未确认前，不把参考资产正式复制或再分发进项目。
23. 单指 IK 只优化该指主动关节：Thumb 3 维，Index 2 维，Middle 1 维，Ring 2 维，Little 2 维。六个被动关节由 MJCF 多项式唯一派生，完整 16 维状态用于 Pinocchio FK。
24. 10 维主动命令顺序固定为 thumb_roll、thumb_abad、thumb_mcp、index_abad、index_pip、middle_pip、ring_abad、ring_pip、pinky_abad、pinky_pip。左右手使用各自符号与限位。
25. 单指损失固定为指尖位置平方误差除以该 O10 完整指链长度的平方。候选质量使用位置误差除以指链长度的无量纲残差；每指阈值可配置，拇指可与其余四指不同。
26. IK 候选只有在求解器可用、所有数值有限、主动关节在限位内、派生完整状态合法且归一化残差达标时才有效。求解器停止原因和候选有效性分别记录；达到评估或时间上限不自动失败，正常收敛也不自动成功。
27. Phase 1 单指求解器使用 NLopt `NLOPT_LD_SLSQP` 局部有界优化。第一次求解以主动关节范围中点为初值，后续以该指上一有效解 warm start；不使用全局搜索、多初值搜索或 16 关节独立优化。
28. 运行时解析梯度由 Pinocchio 在 LOCAL_WORLD_ALIGNED 表达的完整指尖平移雅可比与 MJCF 主动—被动耦合解析雅可比按链式法则组成。中心差分只用于离线验证，不进入实时路径。
29. 单指失败时若已有上一有效解，该指保持上一有效目标，其他成功手指继续更新并显式报告保持。五指尚未各自获得首次有效 IK 时，整侧不发布组合目标。
30. IK 通过有效性判定并组合为 10 维主动目标后，重定向节点才执行按实际输入时间间隔更新的一阶低通。滤波系数为 `1-exp(-dt/tau_j)`；dt 使用连续实际滤波更新对应的 Raw ROS 接收时间，不使用 Rokoko source timestamp 或 IK 完成墙钟时间。
31. 首次就绪时软目标直接初始化为当次组合 IK 目标。单指失败且有历史目标时，滤波继续朝保持目标更新。整侧无效、stale 或时间倒退/重复时不更新滤波状态，也不发布软目标。
32. 重定向输出 `/o10_control/{side}/command` 的标准 JointState。header 时间继承触发 Raw 接收时间，frame_id 为空；name 必须是固定 10 名称，position 是 rad 软目标，velocity 和 effort 为空。未就绪时仍可发布合法软目标用于诊断和录制。
33. stale 发生时保存软目标、冻结正常历史并停止发布。恢复候选区与正常历史隔离；只有整侧 Raw、掌坐标、五指当前长度和五指当前 IK 全部有效的帧才计入恢复。
34. stale 恢复同时要求连续 K_recover 帧和 T_recover_min 观察时间，任一坏帧或时间异常清零。恢复成功首帧发布 stale 前保持目标并重置滤波时间，下一帧再用既有低通追赶当前 IK；不增加第三个插值器。
35. 重定向节点发布逐侧 RetargetingState，完整表达状态发布时间、关联 Raw 时间、求解完成时间和耗时、整体阶段、ready、stale、是否发布命令、逐指长度/IK/历史保持/残差、NLopt 结果与评估次数及恢复进度。缺失残差使用 availability=false 和 NaN，不用 0。
36. O10 控制节点必须严格重新验证软 JointState 的 name、position、header、年龄、空 velocity/effort、有限性和侧别限位。无效目标整侧拒绝，不发布，也不推进控制基准；另一侧不受影响。
37. 控制安全不得依赖 RetargetingState；它从自己实际收到的合法软目标、上游时间、本机接收时间、真实反馈、错误监控和锁存故障独立派生状态。运动使能不再需要操作者 arm 授权。
38. 每侧运动许可等于 feedback_ready、error_monitor_ready、target_ready、target_fresh、非 fault_latched 的逻辑合取（arm 已随 `4fedfaa` 移除，对齐官方 SDK 直控）。它是只读派生值，不是另一个可写开关。
39. 控制节点通过 Adapter 在不先移动硬件的前提下独立读取一帧新鲜合法 10 维主动关节状态，用其初始化最终限速位置基准。没有反馈时该侧保持未初始化并禁止发送；不得用零位、中点、首目标或旧进程缓存代替。
40. 最终关节变化率限制以每侧上一条实际发送命令为基准，使用处理新目标时读取的本机单调时钟。每关节允许变化量为配置最大变化率乘以封顶后的有效时间额度，输出逐关节裁剪后再次验证。
41. 控制入口保持事件驱动：每条新鲜合法软目标最多产生一条最终命令；没有新目标时不建立周期追赶定时器。发布成功后才原子推进上一发送命令和单调时刻，任何失败都不推进。
42. 控制节点向 `/o10/{side}/joint_cmd` 发布最终 JointState，header 保留软目标 header，position 是硬限速后的 10 维命令，name、velocity、effort 为空。软目标与最终命令均可被外部 MCAP 录制。
43. 运动由发布到 `/o10_control/{side}/command` 的新鲜合法软目标直接驱动；目标 2 秒内不更新（`target_fresh=false`）即自动暂停，停止发布就是停止控制。操作者唯一的状态转换操作是逐侧 `/o10_control/{side}/clear_fault`；它使用空请求的 `ControlOperation` 类型，响应包含 success、稳定结果码、可读 message 和原子生成的操作后 O10ControlState。`arm`/`disarm` 随 `4fedfaa` 移除。
44. 只有 feedback_ready、error_monitor_ready、target_ready、target_fresh 且无锁存故障成立时，控制节点才把新鲜合法目标转换为最终命令；条件不成立则跳过该目标并报告 `VALID_MOTION_DISABLED`，不发送命令、不推进限速基准。
45. 使能失败只反映当前技术前置条件不成立，不排队或缓存目标；条件恢复后由下一条新鲜合法目标自动生效，无需任何人工授权步骤。
46. 停止控制的唯一方式是停止发布新目标；目标过期（`target_fresh=false`）即暂停发送且不再产生新命令，不自动张手、回零、追赶旧目标或断开驱动。目标恢复再生效即自动恢复运动。
47. 设备状态一旦变得不可信（断连、重启、非法反馈、回读或错误监控超时），进入锁存故障并废弃旧位置基准；故障消失后不会自动恢复运动。
48. clear_fault 只清控制节点锁存，不复位厂商硬件错误。真正执行时中止产生新命令，再同步查询新的错误状态、确认 10 关节"致命"错误位（bit0–bit3）全零与通信健康、独立读取并验证新的真实位置、重新初始化限速器，最后清锁存。
49. clear_fault 任一步失败都保持 fault_latched=true，不发送位置、不恢复旧基准、不部分清除、不排队或自动重试。请求时本来无故障且状态一致则幂等成功，不重新读硬件、不重置限速器。清除成功后运动不立即恢复，服从下一条新鲜合法软目标。
50. O10 错误状态必须由 Adapter 主动轮询；没有错误消息不能解释为健康。任一关节任一"致命"错误位（bit0–bit3；`commu_except` bit4 为厂商历史标记，不锁存）、命令回读超时、非法反馈、安全不变量失效、控制/Adapter/设备重启断连或错误监控超时都会锁存故障并停止运动。
51. 命令—反馈跟踪误差暂不作为锁存条件，直到厂商反馈被确认是独立物理测量而不是命令回显。该未知不得阻止已有错误位、超时和反馈格式安全检查。
52. 控制节点发布逐侧 O10ControlState，表达触发事件、阶段、反馈/错误监控/目标状态、fault_latched、motion_enabled、目标处理结果、是否发布、逐关节限速介入、故障位掩码、厂商错误位和关键时间及 availability。
53. RetargetingState 和 O10ControlState 都是事件驱动、可录制、只读诊断接口。状态 Topic 丢失、延迟或消费者异常不得改变控制决策。
54. 正式运行的硬件 Adapter 继续隔离 CAN、RS485、USB、设备 ID、SDK 和实体设备生命周期。它必须补充无动作的独立关节读取能力和主动错误查询能力；若做不到，控制侧保持不可运动，不降低安全前提。
55. 自动化测试专用 Adapter 必须是纯软件实现，不加载厂商动态库、不打开设备文件、不访问 CAN/RS485/USB、不发现或命令真实 O10。它在相同公开 Adapter 接口上模拟反馈、错误、超时、回读、重启和断连。
56. 所有尚未有实验依据的数值，包括人体长度窗口、稳定阈值、IK 残差、SLSQP 停止条件、低通时间常数、stale、恢复帧数/时长、目标新鲜度、错误轮询、回读/清故障超时、关节最大变化率和时间额度，均为显式配置。不得为完成实现而把猜测值包装成安全默认值。
57. 当前可追溯模型基线是 ManusOmniBridge commit `f4fd0d913c2151bcb4be0d29fbc02761b9638009`。模型文件正式 vendoring 和发布必须在许可确认后进行；在此之前可通过外部只读 fixture 完成模型算法开发。

## Testing Decisions

1. 自动化测试明确为无真实硬件测试。任何测试进程不得加载或启动厂商 O10 节点、SDK 动态库、CAN、RS485、USB 或实体设备发现；测试硬件 Adapter 是纯软件替身。
2. 唯一主测试接缝是完整 ROS 图的公开接口：测试从 UDP 发送 Rokoko JSON v3，运行真实接收、重定向和控制节点，在末端连接纯软件 Adapter，并通过公开 Topic 与 Service 观察行为。
3. 主接缝不直接调用 JSON 解析私有函数、人体坐标构造、长度估计、IK、滤波、限速或状态机私有方法。实现内部可以重构，只要外部 Topic、Service、时间、状态和失败行为不变，主测试就不应修改。
4. 软件 Adapter 提供可控的初始关节位置、正常回读、10 关节错误位、错误查询超时、反馈读取超时、命令回读超时、非法反馈、重启和断连场景；每个场景必须可确定性触发，且默认绝不转发到真实设备。
5. 仓库已有 O10 控制 ROS 图测试可作为 prior art：测试节点发布上游 JointState 并观察左右最终命令，验证启动静默、左右路由和坏侧不阻塞好侧。目标实现将该 seam 扩展到完整链路，并把当前“合法目标直接转发”的预期替换为使能、反馈初始化与硬限速后的外部行为。
6. JSON fixture 至少覆盖官方 JSON v3 完整双手、仅左、仅右、节点乱序、节点缺失、重复名称、Actor 索引不存在、非法 JSON、NaN/Infinity、非法四元数和场景字段错误。测试验证发布 Topic、规范顺序、共享接收时间及逐侧丢弃，不断言解析器内部调用。
7. QoS 集成测试验证 Reliable Raw 发布者能连接 BestEffort KeepLast(1) 重定向订阅者和 Reliable 录制观察者；高频输入造成下游滞后时，不应形成按旧帧顺序长时间追赶的行为。Deadline/Lifespan 不作为 pass/fail 安全信号。
8. 归一化与长度状态通过一段合成稳定骨架序列从 Raw Topic 驱动，观察 RetargetingState 从 collecting 到 frozen、waiting-first-IK 和 tracking；异常骨长只影响对应指或整侧掌坐标，冻结估计不被静默修改。
9. 重定向行为测试覆盖左右手五指、手掌世界平移/旋转不改变掌内目标、不同绝对人体手型映射到一致归一化方向、单指失败历史保持、首次失败阻止整侧就绪、掌坐标退化整侧不发布以及左右状态隔离。
10. IK 外部测试观察软 JointState 和 RetargetingState，验证固定名称顺序、左右限位、残差 availability、求解停止码与候选有效性分离、失败保持标志和 header 时间继承；不检查 NLopt 内部迭代路径。
11. 解析耦合梯度作为必要离线契约检查：中心差分独立对比解析梯度，覆盖左右手、五指、多组可行域内部状态、接近限位但差分仍合法的状态，并特别覆盖左右拇指不同 DIP 多项式。
12. 模型资产离线检查验证 provenance 哈希、左右 URDF/MJCF 同版、Pinocchio 16 维模型、固定主动顺序、左右限位、所需 palm/root/tip frame、严格六条耦合和有限系数。资产篡改或结构错配必须使初始化失败并对外进入 MODEL_ERROR，而不是继续求解。
13. 软平滑测试使用可控 Raw 接收时间序列，观察软目标满足按 dt 的一阶低通、首帧初始化、时间重复/倒退拒绝、单指保持和整侧无效不推进。测试比较外部软目标，不调用滤波器内部对象。
14. stale 与恢复测试停止一侧 Raw，观察该侧进入 stale 且停止软目标；恢复序列中的任一坏帧重置计数；同时满足连续帧和时长后首目标等于 stale 前保持值，下一帧才开始低通追赶。另一侧持续运行。
15. 控制启动测试让软件 Adapter 暂不提供反馈或错误状态，验证 motion_enabled=false 且无最终命令；提供合法反馈和全零错误后只改变 ready 状态，仍不会因目标就绪而擅自运动（需目标同时新鲜）。
16. 直驱使能测试验证每侧在 feedback_ready、error_monitor_ready、target_ready、target_fresh 且无锁存故障时自动使能；任一无就绪或目标 stale 时跳过目标并报告 `VALID_MOTION_DISABLED`，不发送命令。应答状态和同事件状态 Topic 必须一致。
17. 暂停测试验证停止发布新目标后 `target_fresh` 变 false、停止产生新硬件命令、不张手/回零/追赶旧目标；重新发布新鲜目标后经有界过渡自动恢复，无需任何授权步骤。
18. clear_fault 测试按软件 Adapter 故障注入覆盖通信不健康、错误查询超时、错误格式非法、"致命"错误位（bit0–bit3）仍存在、反馈读取超时、反馈非法和限速器初始化失败；每种失败都保持锁存。成功路径验证新真实位置成为限速基准且 `commu_except`（bit4）不阻止清除。
19. 最终硬限速测试使用可控单调时钟，验证逐关节正负方向裁剪、不同关节速率、时间额度封顶、无效目标不推进基准、发布失败不推进状态和左右独立。外部只观察最终命令与 O10ControlState.slew_limited。
20. 锁存故障测试通过软件 Adapter 注入任意"致命"错误位、回读超时、非法反馈、错误监控超时、重启和断连，验证原子 fault_latched=true、停止后续命令、原因掩码可组合、条件恢复不自动清除（`commu_except` 不锁存）。
21. MCAP 验收使用外部 rosbag2 录制 Raw、RetargetingState、软目标、O10ControlState、最终命令和软件反馈，验证 Topic 可被发现和记录、时间字段语义可关联且节点本身不写 MCAP。该测试不声称 DDS Reliable 能覆盖 UDP 丢包、进程崩溃或磁盘故障。
22. 性能基准在无真机环境中分别测量每侧 IK 耗时、双手持续吞吐和端到端年龄，报告分布而非只给平均值。Phase 1 的运行配置必须把 Rokoko 频率设为低于测得的可持续 IK 吞吐；未达到目标时降低输入频率，不在本 spec 中新增调度算法。
23. 自动化测试通过只证明软件链、接口、数学与状态机，不替代真机安全验收。所有依赖实体 O10 的速度舒适性、反馈物理语义、设备 watchdog 和通信时序结论均标为未验证。

## Out of Scope

- 真实 OmniHand O10 真机测试、硬件 smoke test、速度舒适性标定和物理安全认证。
- 机械臂、腕部位姿、手臂轨迹或全身遥操作。
- 触觉、力/力矩、阻抗控制、混合位置力控和碰撞感知。
- 6 个被动关节的独立命令；它们只参与运动学派生。
- 多 Actor 同时控制、多对 O10 多实例部署或运行中切换操作者。
- 操作者档案、永久手型数据库、规定手势校准或运行中自动重估冻结长度。
- 全局 IK、多指联合优化、多初值搜索、自碰撞/环境碰撞损失、指尖方向损失和学习型重定向。
- 自动过载调度、latest-only 工作线程、回调抢占或动态调整 Rokoko 频率；Phase 1 由操作者配置低于 IK 吞吐的输入频率。
- 在 Raw 节点、人体指尖目标或 IK 损失之前增加滤波；Phase 1 只有 IK 后软低通和控制端最终硬限速。
- 第三套 stale 恢复插值器。
- 自动张手、回零、断开驱动、硬件急停或厂商故障复位。
- 将命令—反馈跟踪误差用作锁存故障，直到厂商反馈物理语义得到证实。
- 节点直接写 MCAP；录制属于外部 rosbag2 职责。
- 正式复制或再分发许可尚未确认的 O10 上游模型资产。
- 为尚无实验依据的安全、性能和滤波参数编造最终默认数值。
- Xacro 运行时生成、MuJoCo 在线求解、PyBullet IK、碰撞模型、网格、RViz 或仿真场景运行依赖。

## Further Notes

- 当前控制实现是 AS-IS 基线而不是安全目标：它已经证明双侧 Topic 路由、启动不主动发命令、10 维有限值与侧别限位检查，但仍会把合法目标直接转发。实现应以现有 ROS 图测试为 prior art，逐个垂直切片替换外部行为，不能保留一条绕过使能与硬限速的兼容直通路径。
- Rokoko 官方 Custom Streaming 文档确认 JSON v3 存在 `version`、`fps`、`scene.timestamp` 和 `actors` 等结构，并采用 UDP 低时延传输；但当前公开证据不足以安全固定全部 21 节点原始拼写、timestamp 单位和 epoch。正式实现必须先把用户指定的官方示例存为 fixture，再由 fixture 固定这些事实。
- 尚未标定参数必须集中配置并带单位、取值约束和来源说明。第一次软件实现可以提供“实验配置”，但不得标成经过真机验证的安全默认值。
- 当前 O10 参考模型基线和接口事实来自只读上游参考。URDF 线性 mimic 不代表真实非线性耦合，也没有证据证明 PyBullet 自动执行 mimic；在线算法以显式 MJCF 多项式派生为准。
- 无真机软件 Adapter 是测试依赖，不是生产控制路径。生产 Adapter 必须通过显式启动配置或构建/launch 选择，测试运行必须具备防止误加载厂商节点和设备库的硬隔离。
- 实现完成的定义是：无真机完整 ROS 图验收、离线数学/资产检查和静态/构建检查全部通过，且所有未进行的真机验证被清楚记录。它不等于实体手已经安全可用。
