## T08：Provider 与 Adapter 契约

测试入口：`omnihand_o10_hardware_adapter/test/`。

正式 Agilink SDK v1.1.8 的外部只读源码/CPython wheel 已核对，并在工作区外 mamba 环境安装。当前 23/23 测试覆盖：

- 命令、反馈、错误查询和 `ReadO10ActiveJoints` 的 schema/接口映射；
- 六类 factory transport 参数的显式传递；
- 每次主动关节读取均发起新读取，不返回历史 `joint_states` 缓存；
- 缺少 SDK、参数或构造条件时 fail-fast；
- USB/厂商 transport 选择与生产 composition 的边界。

这组测试证明 Provider 的接口契约和错误处理形状，不证明真实 factory、物理错误位含义、反馈时序或真机动作。外部 SDK 源码固定 commit 为 `026740d9fdd8ba32b0605fa702a992b322076f1b`。

## T09：生产 composition

测试入口：`rokoko_omnihand_bringup/test/test_production_launch.py`。

结构测试 2/2 通过，断言生产 launch 只包含三个业务节点、生产 Adapter/shim 和外部厂商 launch；不加载 `rokoko_omnihand_system_test` 或纯软件 Provider。参数文件、vendor launch 路径和 Provider 两侧 transport 参数均显式必填，缺失或 SDK 构造失败即启动失败。

该测试不启动真实设备，不验证 vendor launch 的物理行为。

## T10：无真机端到端 ROS 图

测试入口：`rokoko_omnihand_system_test/test/`。

在真实模型/Pinocchio/NLopt mamba runtime 下，公共 ROS 图 21/21 通过：

```text
UDP fixture → Rokoko receiver → hand retargeting → O10 control → software Provider
```

覆盖内容：

- 成功路径从 UDP 到最终命令；
- 错误位、错误查询超时、反馈读取超时、回读超时、非法反馈、非法错误状态、重启和断连；
- 通过公开 Topic/Service 观察 Raw、状态、软目标、最终命令和反馈；
- 外部 rosbag2/MCAP 可录制性，节点不直接持有 MCAP writer；
- 双侧输入吞吐和接收年龄基准。

T10 的 Provider 是确定性软件实现，禁止依赖生产硬件 Adapter、厂商节点、SDK、动态库或设备 API。因此 21/21 是无真机系统图通过，不是 O10 真机通过。
