# 02 — 编排核心：期望状态与替身进程

**Spec:** [08_Launchpad 网页一键启动遥操作系统 Spec](../../08_Launchpad网页一键启动遥操作系统Spec.md)

**What to build:** 通过 HTTP/WebSocket API 提交七方块（四个业务节点名、sim provider、合成输入源、录制器）的点亮集合，编排器以替身可执行进程（可控启动延迟、可注入崩溃、可发布假状态消息的 stub）按依赖顺序真实拉起/停止进程：全启动顺序化、全停反序、整体重启、单节点启停（停止返回下游影响提示）、崩溃检测告警但不自动拉起。方块网格的期望状态模型与五条组合校验规则（hcan×sim 硬阻止、合成输入+hcan 需二次确认、混流黄提示、孤儿组合黄提示不阻止、preflight 随方块集条件化的检查框架）在 API 层完整生效。进程安全底线落地：业务进程全部为编排器子进程并设置 PDEATHSIG，编排器被 kill -9 时全体替身跟随退出。本 ticket 的主接缝 API 测试（替身进程 + API 黑盒）成为后续所有编排行为的测试基建。

**Blocked by:** 01 — 包骨架与架构治理落地。

**Status:** ready-for-agent

- [ ] API 提交方块集启动，替身进程按依赖顺序出现，进程清单与期望/实际状态可查询
- [ ] 全停反序、整体重启、单节点启动/停止均可经 API 完成，停止返回下游影响提示
- [ ] 替身进程被 kill 后编排器检测并上报告警状态，不自动重新拉起
- [ ] hcan 与 sim 方块同亮被硬阻止；合成输入+hcan 组合返回需二次确认标志；混流与孤儿组合返回黄提示
- [ ] preflight 检查框架就位且由方块集条件化（不相关检查不执行）
- [ ] 编排器被 kill -9 后所有替身进程跟随退出，无孤儿进程
- [ ] 侧别（双侧/仅左/仅右）作为启动参数进入编排模型
- [ ] 主接缝 API 测试覆盖以上全部行为并全绿
