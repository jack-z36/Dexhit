## 0. 调研结论摘要（Phase 1–4 已完成）

**项目事实**（来源：仓库全量探查）：Rokoko → OmniHand O10 实时手部遥操作系统，10 个 ROS 2 包位于 `src/collection/omni_hand/`。真实数据流：

```
Rokoko Studio UDP(14043, LZ4 JSON v3, 30fps) / fixture 回放 / 合成场景
 → rokoko_hand_receiver → /rokoko/{left,right}/raw_hand (RawHandFrame)
 → hand_retargeting    → /hand_retargeting/{side}/state (RetargetingState)
                        → /o10_control/{side}/command (JointState×10，仅 ready 后发布)
 → omnihand_o10_control→ /o10/{side}/joint_cmd (限速后) + /o10_control/{side}/state (O10ControlState)
 → Provider(software_o10_provider 可注入故障 / 生产 Agilink)
                        → /o10/{side}/joint_states + joint_error_states + read_active_joints srv
外部录制: ros2 bag record --storage mcap
```

已有无真机验收能力：`rokoko_omnihand_system_test/graph.py::RosGraph`（进程内真实四节点 + loopback UDP）、`scenes.py::scene_payload()`（刺激源）、`/o10/{side}/test_injection`（9 种故障注入）、`test_t10_mcap.py`（MCAP topic 清单）。构建/测试命令与 Python 3.12/mamba 环境坑已有权威记录（`DOCS/03_工程/03_测试总览与追踪矩阵.md`、交接文档）。

## 1. Workflow 状态机（SKILL.md 核心）

```
Human Acceptance Goal
 → PLANNING（编排者建 run 目录、manifest、把目标转为首个 Experiment Request）
 → EXPERIMENTING → Raw Experiment Report
 → ANALYZING ─┬─ 证据不足 → NEED_MORE_EVIDENCE → 新 Experiment Request → EXPERIMENTING（补充实验 ≤3 轮）
              └─ 证据充分 → ROOT_CAUSE_CONFIRMED（或 VERIFIED_PASS：无缺陷直接终局）
 → SOLUTION_PLANNING → Solution Proposal + Micro Tasks
 → EXECUTING（每 task 一个 Execution Agent；单 task 修复 ≤3 轮）
 → REVALIDATING（强制重新 EXPERIMENTING→ANALYZING，铁律：Execution 完成 ≠ 验收完成）
 → VERIFIED_FAIL → 回 SOLUTION_PLANNING（整循环 ≤3 次，超限人工）
 → VERIFIED_PASS → FINAL_REPORT
终态：VERIFIED_PASS / VERIFIED_FAIL / NOT_VERIFIED / EVIDENCE_INSUFFICIENT / BLOCKED / OUT_OF_SCOPE
```

## 2. 四 Subagent 职责、I/O 契约与模型分配

| 角色 | 只答 | 输入 | 输出（落盘文件） | model / effort | 写权限 |
| --- | --- | --- | --- | --- | --- |
| Experiment | What happened | `experiments/EXP-nnn/request.md`（ID/目标/环境/前置/刺激/步骤/观测信号/采集物/时长停止条件/重复次数） | `raw-report.md`（环境快照、code revision、命令、原始观测、topic 数据、日志、时序、退出码、产物清单、缺失数据、执行错误——纯事实） | `gpt-5.6-luna` / medium | 可执行测试与采集命令；**禁**改 `src/`、禁因果判断、禁方案、禁把"没观察到"写成"不存在" |
| Analysis | Why | Spec 预期 + 全部 raw-report + 代码/架构上下文 | `investigation/report.md`（Ideal/Observed/**First Divergence 沿 P0→P6**/Cause/F evidence 引用/Rejected Hypotheses/Remaining Uncertainty/Confidence；每句标注 FACT/INFERENCE/HYPOTHESIS/CONFIRMED/UNKNOWN）或新 Experiment Request（含区分哪些 competing hypotheses） | `gpt-5.6-sol` / high | 只读代码 |
| Solution | What should change | Investigation Report + ARCHITECTURE/ADR/约束 | `solution/solution.md`（Target State/变更/影响模块/回归与安全风险/验证策略）+ `tasks/TASK-nnn.md`（Goal/Context/Allowed/Forbidden Scope/Required Changes/Acceptance Criteria/Verification Command/Dependencies，单片一上下文可完成） | `gpt-5.6-luna` / high | 只读 |
| Execution | Make the change | 单个 Micro Task + 最小上下文 | `execution/TASK-nnn-report.md`（Files Changed/Behavior/Commands/Developer Verification/Unexpected Findings/BLOCKED 项/Not Verified）；最多说"task implemented"，禁宣称问题解决或验收 PASS | `gpt-5.4` / high | 可改代码但限 task 范围；禁顺手重构、禁 git commit |

派发规则：每次 spawn 显式指定 model+reasoning_effort；模型不在 allowlist 或派发失败 → 回落 `[agents]` 默认（luna/high）；`zai/*`、`deepseek/*` 列为可选并标注"跨 provider 委派未验证"。主派发路径**不依赖角色文件**——编排者用 `references/agent-roles.md` 模板组装完整 message（Codex `multi_agent_v1__spawn_agent(fork_context=false)` 与 ZCode Agent 工具均适用）；角色文件是 Codex 端的命名快捷方式。

## 3. 探针点（Probe Points，全部来自真实仓库）

`references/probe-points.md` 逐点定义：数据来源、消息类型、采集命令、保存格式、对齐方式（P1 header.stamp=接收时刻，P3/P4 继承上游 stamp，可跨探针对齐）：

- **P0** UDP 输入：loopback `scene_payload()` 回放 / `captured_left_glove_v3.lz4` fixture / 真实 14043
- **P1** `/rokoko/{side}/raw_hand`：`ros2 topic echo` / MCAP；receiver 日志（"listening…"、"dropped…"，2 的幂次节流）
- **P2** `/hand_retargeting/{side}/state`：phase/length_state/逐指 ik_result 枚举
- **P3** `/o10_control/{side}/command`：JointState 10 关节（仅 command_published 时存在）
- **P4** `/o10/{side}/joint_cmd` + `/o10_control/{side}/state`：slew_limited[10]、fault_reason_mask
- **P5** `/o10/{side}/joint_states`、`joint_error_states`、`read_active_joints` srv、`test_injection`
- **P6** MCAP：`ros2 bag record --storage mcap`（沿用 test_t10 的 topic 清单）

实验 harness 三档：A) `RosGraph` 进程内图（默认，无真机）；B) /tmp colcon 工作区 + `ros2 run/launch` 进程级；C) 真机/生产 Provider（**强制人工 checkpoint**，遵守编程执行规则 §10 验证阶梯）。

终局结论影响进度时，仅在 `DOCS/03_工程/` 记摘要（引用 runs/ 相对路径），raw 证据不搬入 DOCS（三层记忆规则）。不创建 `.acceptance/` 新根目录（任务书允许且要求优先沿用既有结构）。

## 5. Main Orchestrator 职责与 Role Violation 检查

编排者只做：状态管理、派发、上下文打包（切片：单实验/单任务只给所需 Spec 节+不变量+相关 raw-report，禁整库）、输出验证、产物路由、循环控制、人工 checkpoint、终局报告。**不代替四角色做核心工作。**

输出验证（具体判据写入 SKILL.md）：Experiment 报告出现因果/意图语句（"原因是/应该是/fail 了/有 bug"等非原始字符串）→ ROLE_VIOLATION 退回重写；Analysis 无 evidence 引用或证据不足直接给方案 → 拒收；Micro Task 大于单上下文 → 退回重拆；Execution 越权修改 → 停止流程。人工 checkpoint：真机/生产 Provider/外部 SDK、破坏性操作、证据预算耗尽、Spec 与现实矛盾需改预期。
